## 3. Web 测试流程

1. 新存档启动：欢迎弹层可关闭；检查首次引导的遮罩、高亮区域和文本。
2. 引导第三步：在高亮输入框录入文本，确认键盘输入、提交召唤和继续引导都可操作。
3. 待办闭环：选情绪和难度，召唤任务；完成后确认收服状态和图鉴变化。
4. 图鉴：检查伙伴不同形态、未发现灰显、装扮与纪念品分类及详情图尺寸。
5. 心屿和专注：检查地图显示、角色位置与移动、专注时长选项和开始按钮。
6. 回廊：先确认入口解锁状态、选中出战伙伴、行动力和当日次数，再尝试进入；分别测试点击、键盘方向、撤销和重开。
7. 成长与存档：检查页面入口、导出/导入，并重载页面确认 Web 存档恢复。
8. 窄屏与桌面：分别检查对话框、分类栏、路线卡、贴纸图和回廊画布布局。
9. 音频：首次操作后确认 BGM 启动；检查晴朗/薄雾/夜晚映射、静音、标签页切后台/返回恢复和循环接缝；触发任务添加/完成/收服/升级、回廊提灯/拾取/阻挡、心屿点击，确认提示音顺序与音量。

## 4. Web 反馈复核结论（2026-09-28，真实浏览器 + 自动化测试）

此前记录的两条反馈已在当前构建上复核，**均未复现**，测试环境：Chrome 内核 900×700 视口、`--pwa-strategy=none` 新构建、全新存档；截图证据在 `docs/qa/2026-09-28-web-验收/`。

- **引导第三步输入框无法输入 → 未复现。** 全新存档走引导：第 3/9 步高亮添加面板，点击输入框、键入“写周报”、点「召唤」全部正常，任务入列并自动放行到第 4/9 步（证据 02、03）。自动化回归 `引导第三步输入框可直接输入，召唤后自动放行` 常驻守护。旧报告应来自旧版本构建（当时存在 AppBar 标题溢出等渲染异常，已修复）。
- **回廊入口一直灰显 → 未复现（且“灰显”本身是未解锁设计）。** 收服伙伴后，雷鸣丘（第 0 区）入口为橙色可用，点击即进入迷宫；灰色按钮仅出现在未解锁区（需累计探索 3/6/10… 次，行内有进度说明）（证据 05）。此前“点击无反应”的场景是无出战伙伴：现按钮可点并弹提示说明缺什么（自动化回归已断言按钮可用 + 提示文案）。进入后新贴图、天气怪立绘、Boss、传送门、神龛、出口梯全部正确渲染（证据 06），方向垫移动、墙壁碰撞（“过不去”提示）、步数计数正常（证据 07）。
- **其他 Web 视觉复核。** 伙伴详页/未发现灰影、专注主按钮与云游路线插画在 2026-09-28 Chrome 视口完成检查（证据 08–11）。回廊视觉只抽查雷鸣丘；其余九区尚未逐区检查。该组记录不代表 Android 设备验收。

### 复核中发现的小瑕疵（2026-09-28 已修复）

1. **引导等待步骤的一帧跳步窗口 → 已修复。** 等待类步骤的高亮洞在下一帧才设置，此前该瞬间点击会触发全屏“点击推进”。现在等待步骤在洞就绪前只拦截不推进；新增单测“引导等待步骤在洞就绪前只拦截不推进”与“引导普通步骤点击空白处推进”守护该行为。
2. **收服成功弹窗立绘瞬态占位 → 已修复。** 弹窗改为先用 `precacheImage` 解码立绘再入场，不再出现灰色占位圆。
3. **Web 端 CJK 字体依赖 fonts.gstatic.com → 已修复（主体）。** 新增 `tool/subset_font.py`：收集工程实际用字（1713 个唯一字符）并把全量 Noto Sans SC（SIL OFL 1.0，见 `assets-src/fonts/OFL.txt`）裁剪为约 0.44 MB/字重的子集，随包分发为 `MoodisleSans` 字族并在主题全局引用。实测主题文本已使用包内字体（对照组实验：注入无效字体族时 gstatic 回退切片从 9 升至 21）。边界：CanvasKit 对少量绕过应用主题的框架内部文本仍按需请求约 9 个回退小切片（首访约几百 KB，浏览器缓存后不再下载），完全离线的首次访问这部分可能显示回退字形；迷宫画布内文字已显式引用包内字体。

## 6. 仍需开发者确认的回归

2026-09-28 的全量回归基线为 17 个测试文件、106 条测试全部通过。音频接入后，2026-09-30 全量重跑时发现 4 个失败并修复：2 个 widget 测试因 just_audio 平台通道在测试进程无实现抛出未捕获 MissingPluginException（现由 `app/test/flutter_test_config.dart` 注入 `JustAudioPlatform` 替身，测试中音频无声即预期）；`systems_test.dart` 的明信片/成就断言依赖 `SocialState.hasVisitor` 读取真实时钟，固定夹具日期跨过 72h 客住窗口后失效（夹具改为相对当前时间）；teardown 删除临时目录在 Windows 偶发句柄锁（改为重试删除，且 `getTemporaryDirectory` mock 单独指向系统临时目录，避免 just_audio 资产缓存写入存档目录）。修复后复跑 106/106 通过，`flutter analyze` 无问题。历史旧版 89 项通过和 domain 覆盖率 93% 不作为当前结论。

迷宫规格的字面目标为每区 1,000 个种子、共 10 区；当前 `maze_generator_test.dart` 实际覆盖每区 100 个种子、共 1,000 组。生成/求解低于 50ms 与 1,000 局低于 5s 也没有当前性能基准记录。目标口径与覆盖差距见 [迷宫引擎详细设计](04-迷宫引擎详细设计.md) §7。Android APK 可交付与全平台验收仍需按 §5 完成后才能宣称。
