## 2. 环境与命令

需要 Flutter SDK 和 Dart 3.3 或更高版本（低于 4.0）。

    cd app
    flutter pub get
    flutter run -d chrome
    flutter run                 # Android 设备或模拟器
    flutter analyze
    flutter test
    flutter build web --release
    flutter build apk --release

Flutter 3.47 起不再默认生成或管理缓存型 Service Worker；旧版 `--pwa-strategy=none` 已弃用，因此当前构建命令不再携带该参数。若以后需要离线缓存，应单独实现并验收自定义 Service Worker。

### iOS：Windows 开发、GitHub Actions 构建

为控制 macOS runner 使用次数，`.github/workflows/ios-build.yml` 只有 `workflow_dispatch`，不会随 push、pull request 或定时任务运行。先确认同一提交的常规 Linux CI 已通过，再进入仓库 **Actions → iOS Build → Run workflow**：

- `unsigned-app`（默认）：执行一次无签名 Release 编译并上传 `Moodisle-unsigned-iOS-app`，用于确认 Flutter、Swift 壳、插件和资源能在 Xcode 中编译。该 zip 不能安装到 iPhone。
- `signed-ipa`：同样只编译一次，随后使用仓库 Secrets 在 runner 本地签名并上传 `Moodisle-signed-iOS-IPA`。产物和日志保留 3 天；同一分支重复触发时，新任务会取消旧任务。

签名模式要求 Apple Developer 账号先创建与 `dev.moodisle.moodisleApp` 完全匹配的显式 App ID、代码签名证书和包含目标 iPhone UDID 的 provisioning profile，然后在仓库 Settings → Secrets and variables → Actions 中配置：

| Secret | 内容 |
|---|---|
| `IOS_CERTIFICATE_BASE64` | 导出的 `.p12` 证书文件的 Base64 内容 |
| `IOS_CERTIFICATE_PASSWORD` | 导出 `.p12` 时设置的密码 |
| `IOS_PROVISIONING_PROFILE_BASE64` | `.mobileprovision` 文件的 Base64 内容 |
| `IOS_KEYCHAIN_PASSWORD` | 仅供 runner 临时钥匙串使用的随机强密码 |

Windows PowerShell 可用以下命令转换二进制文件；输出只粘贴到 GitHub Secret，不写入仓库或文档：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("Moodisle.p12"))
[Convert]::ToBase64String([IO.File]::ReadAllBytes("Moodisle.mobileprovision"))
```

资产清点和版权扫描从仓库根目录运行：

    python tool/asset_pipeline.py todo
    python tool/asset_pipeline.py validate
    python tool/ip_scan.py .

## 3. Web 测试流程

1. 新存档启动：欢迎弹层可关闭；检查首次引导的遮罩、高亮区域和文本。
2. 引导第三步：在高亮输入框录入文本，确认键盘输入、提交召唤和继续引导都可操作。
3. 待办闭环：选情绪和难度，召唤任务；完成后确认收服状态和图鉴变化。
4. 图鉴：检查伙伴不同形态、未发现灰显、装扮与纪念品分类及详情图尺寸。
5. 心屿和专注：检查地图显示、角色位置与移动、专注时长选项和开始按钮。
6. 回廊：先确认入口解锁状态、选中出战伙伴、行动力和当日次数，再尝试进入；分别测试点击、键盘方向、撤销和重开。
7. 成长与存档：检查页面入口、JSON 导出/导入，并重载页面确认 Web SQLite 存档恢复。验收首次迁移时，保留原有 JSON 存档，在新数据库初始化后核对任务、伙伴、库存和活动迷宫；不要只清 localStorage 判断数据库是否清空。Web 存储由 Drift 按浏览器能力选择，需在目标浏览器检查持久化模式；如覆盖隐私模式或多标签使用，还应专门检查刷新恢复与跨标签写入。
8. 窄屏与桌面：分别检查对话框、分类栏、路线卡、贴纸图和回廊画布布局。
9. 音频：首次操作后确认 BGM 启动；检查晴朗/薄雾/夜晚映射、静音、标签页切后台/返回恢复和循环接缝；触发任务添加/完成/收服/升级、回廊提灯/拾取/阻挡、心屿点击，确认提示音顺序与音量。（2026-10-01 用户在 Web 与 Android 实测，音效与播放正常）

## 4. Web 反馈复核结论（2026-09-28，真实浏览器 + 自动化测试）

此前记录的两条反馈已在当前构建上复核，**均未复现**，测试环境：Chrome 内核 900×700 视口、`--pwa-strategy=none` 新构建、全新存档；截图证据在 `docs/qa/2026-09-28-web-验收/`。

- **引导第三步输入框无法输入 → 未复现。** 全新存档走引导：第 3/9 步高亮添加面板，点击输入框、键入“写周报”、点「召唤」全部正常，任务入列并自动放行到第 4/9 步（证据 02、03）。自动化回归 `引导第三步输入框可直接输入，召唤后自动放行` 常驻守护。旧报告应来自旧版本构建（当时存在 AppBar 标题溢出等渲染异常，已修复）。
- **回廊入口一直灰显 → 未复现（且“灰显”本身是未解锁设计）。** 收服伙伴后，雷鸣丘（第 0 区）入口为橙色可用，点击即进入迷宫；灰色按钮仅出现在未解锁区（需累计探索 3/6/10… 次，行内有进度说明）（证据 05）。此前“点击无反应”的场景是无出战伙伴：现按钮可点并弹提示说明缺什么（自动化回归已断言按钮可用 + 提示文案）。进入后新贴图、天气怪立绘、Boss、传送门、神龛、出口梯全部正确渲染（证据 06），方向垫移动、墙壁碰撞（“过不去”提示）、步数计数正常（证据 07）。
- **其他 Web 视觉复核。** 伙伴详页/未发现灰影、专注主按钮与云游路线插画在 2026-09-28 Chrome 视口完成检查（证据 08–11）。回廊视觉只抽查雷鸣丘；其余九区的应用内走查待人工（十区怪物立绘与 tile 拼接已于 2026-10-01 完成资产级复核，见 `docs/qa/2026-10-01-迷宫资产复核/`）。该组记录不代表 Android 设备验收。

### 复核中发现的小瑕疵（2026-09-28 已修复）

1. **引导等待步骤的一帧跳步窗口 → 已修复。** 等待类步骤的高亮洞在下一帧才设置，此前该瞬间点击会触发全屏“点击推进”。现在等待步骤在洞就绪前只拦截不推进；新增单测“引导等待步骤在洞就绪前只拦截不推进”与“引导普通步骤点击空白处推进”守护该行为。
2. **收服成功弹窗立绘瞬态占位 → 已修复。** 弹窗改为先用 `precacheImage` 解码立绘再入场，不再出现灰色占位圆。
3. **Web 端 CJK 字体依赖 fonts.gstatic.com → 已修复（主体）。** 新增 `tool/subset_font.py`：收集工程实际用字（2026-10-14 为 1723 个唯一字符）并把全量 Noto Sans SC（SIL OFL 1.0，见 `assets-src/fonts/OFL.txt`）裁剪为约 0.44 MB/字重的子集，随包分发为 `MoodisleSans` 字族并在主题全局引用。实测主题文本已使用包内字体（对照组实验：注入无效字体族时 gstatic 回退切片从 9 升至 21）。边界：CanvasKit 对少量绕过应用主题的框架内部文本仍按需请求约 9 个回退小切片（首访约几百 KB，浏览器缓存后不再下载），完全离线的首次访问这部分可能显示回退字形；迷宫画布内文字已显式引用包内字体。

- iOS 安装门：配置签名 Secrets 后只执行一次 `signed-ipa`，确认工作流内的 profile Bundle ID 校验、`codesign --verify` 和 IPA 上传均成功；将 IPA 安装到描述文件列出的 iPhone。
- iOS 一致性门：在真机依次检查首次引导与第三步文本输入、任务召唤/完成/收服、重启后的本地存档恢复、BGM/SFX/静音、专注中切后台再返回、图鉴与藏品窄屏布局、心屿角色移动，以及回廊触控方向/撤销/重开。记录设备型号、iOS 版本、commit SHA、IPA SHA-256 和结果。
- 设计中的 Android 桌面组件、iOS Live Activity、通知、触感和暗色主题未作为当前已交付能力，属于后续范围（见 docs/07 §4）。音频已于 2026-10-01 分别在 Web 与 Android 实测通过。
- Web、Android 与 iOS 共享 Flutter 页面和领域逻辑，但共享代码与编译成功都不能替代对应设备的交互验收。
