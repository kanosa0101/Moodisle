# 多端对齐与演进计划

更新日期：2026-11-16。实施分支：`feat/wechat-miniprogram`。

## 1. 本轮范围与发现

本轮同时完成共享源码对齐、专注场景与日期分组。云端只做扩展设计，不连接服务、不上传存档。

小程序分支原先落后于 Android/Web 主线四个提交，本轮合入主线 `418e705`。更关键的构建问题是 `bool.fromEnvironment('MOODISLE_MP')` 不把 `1` 当成真值，而工作流传入的恰好是 `1`，可能错误启用 SQLite 或原生插件。现改为显式兼容 `true`/`1`，工作流统一用 `true`，并分别测试两种值。

## 2. 只维护一套业务代码

| 层次 | 共享内容 | 平台边界 |
|---|---|---|
| 领域 `domain/` | 待办、天气、伙伴、迷宫、奖励、截止时间计时 | 不调用 Flutter 插件 |
| 应用 `application/` | 状态变更、事件处理、自动保存、生命周期转译 | 将宿主信号转为统一业务事件 |
| 展示 `presentation/` | 五个 Tab、引导、地图、图鉴、专注、日期分组 | 同一组件适应窗口尺寸 |
| 数据 `data/` | 领域模型、SaveCodec、JSON 交换格式 | 原生/Web 使用 SQLite，小程序使用 JSON 本地存储 |
| 能力 `shared/platform_capabilities.dart` | SQLite、音频、锁屏支持声明与专注文案 | 集中判断构建开关，避免各页面重复判断 |

后续修改业务规则和页面只改 `app/lib` 一处。平台插件、宿主生命周期和构建工具仍需分别验证，不能用“共用源码”代替平台验收。开发分支定期合并主线；小程序手动构建先检查 `origin/main` 是当前提交的祖先，阻止以落后基线打包。

## 4. 专注场景

- 进入专注 Tab 暂停 BGM；专注会话仍存在时，即使返回其他 Tab 也保持安静。离开专注页且会话结束后恢复原有音乐策略。
- 临时停 BGM 与用户的全局静音分开；不改用户静音偏好，不禁用交互音效。前后台限制与浏览器手势要求继续生效；异步加载音乐完成后再次检查临时静音，避免迟到播放。
- 复用心屿地图和伙伴立绘，增加进度环、安静陪伴提示、暂停状态。页面允许纵向滚动，兼容较矮窗口。
- 不改奖励规则、放弃零惩罚规则或截止时间状态机。

## 5. 日期规则与兼容性

未完成任务按 `createdOn`（创建日）倒序分组；已完成任务按新增 `completedOn`（实际完成日）倒序分组。日期使用 `LocalDate`，跨午夜完成归入完成当天。组内未完成任务置顶优先，之后按 ID 倒序。置顶只作用于所在日期组，保留每日归档结构。

旧存档只有创建日，不能推算完成日：统一归入“历史完成 · 完成日期未记录”。新任务首次完成记录日期，重复完成不改日期或重复发奖励；恢复成待办时清空完成日。JSON v2 增加可选字段，旧 JSON 缺失字段可读；旧客户端忽略新字段后再导出会丢失完成日，不应在旧版本间反复覆盖存档。SQLite schema 提升为 v3，v1/v2 自动补可空列，已有伙伴和专注截止时间保留。

## 6. 构建与验收

通用 CI 在 main 和小程序开发分支运行静态分析、领域/界面测试、构建参数测试、资产检查和共享 Web release 构建。小程序包只手动构建，避免每次文档修改消耗额外构建次数。不同端验收必须记录源码提交、构建时间和包类型，不能用旧 `app/build/weapp` 验证本次代码。

建议按同一份测试存档走查：

1. 添加两个日期的待办，跨天完成一项，确认标题、日期组及组内置顶顺序。
2. 导入缺失完成日期的旧档，展开已完成列表，确认历史分组及刷新后保存。
3. 专注页进入/离开、开始/放弃/完成、手动静音后再进出，确认 BGM 策略。
4. 390px 手机宽度、较矮窗口和桌面窗口检查专注画面与地图斜向拖动。
5. Android 验证切应用暂停、锁屏继续；Web/小程序分别验证页面隐藏暂停，避免误称支持锁屏继续。
6. 小程序开发者工具和真机验证启动、JSON 持久化、剪贴板降级；无音频应显示准确提示。

本轮本地验证：Flutter 138/138 测试通过，analyze 零问题；MOODISLE_MP=true 和 =1 两种构建参数各 2 项测试通过；Python 工具 13 项测试通过，资产 278/278 校验通过、台账 322 项审计通过。Web release 已编译。当前旧小程序模拟器记录仅证明 2026-10-24 的旧版本；不作为本次验收证据。

## 7. 云端扩展设计（未实现）

采用离线优先。现有 GameRepository 和本地保存继续负责日常交互，未来另加同步协调器，避免让页面或领域规则直接依赖网络。默认关闭意味着无后台上传、无隐式注册；只有用户明确开启并完成账户绑定后同步。关闭同步立即停止同步任务，并保留本地进度；是否删除服务端副本应为独立操作。

第一阶段建议做用户主动上传/恢复的版本化备份，保留恢复前本地备份和确认界面。第二阶段再考虑自动多设备同步：需要账户/设备标识、全局实体 ID、服务端修订号、幂等请求及删除标记。目前任务整数 ID 是本地序号，不能直接作为跨设备唯一键；晴晶、奖励、专注结算也不能简单逐字段取最大值，避免重复发放。

同步冲突先以完整存档版本选择与备份恢复处理，暂不设计未经验证的自动合并。用户手写任务和情绪信息属于上传范围，需要清楚告知。失败保留本地可玩，网络重试不阻塞保存。未来立项时再确定后端、鉴权、加密传输、保留期限、删除策略及测试预算，本轮不添加空实现或无效开关。
