# 视觉与收藏体验改版设计

日期：2026-09-27  
范围：Moodisle Flutter Web / Android 共用页面与美术资源  
状态：用户已选定图鉴详情方案 A；其余预览方向获认可

## 1. 背景与目标

本轮处理六项相连的体验问题：图鉴详情弹窗太小且角色图偏小；装扮和纪念品缺少完整图鉴；伙伴云游插画太小；回廊地砖、栅栏和怪物的美术语言不一致；此前用 Material 图标替代的 Emoji 缺少统一的贴纸资产；专注开始按钮与纸感卡片风格不合。

Web 与 Android 共用 Flutter 页面、状态和资产路径。本轮通过同一套响应式组件和资源接线维持两端一致。资产按项目原创美术管线生成，不复制只读参考原型的图片或代码。

## 2. 已确认的视觉决定

- 图鉴详情采用方案 A「Web 横向大画册」：大图在左、角色档案和形态卡在右。用户在视觉稿中选定 A。
- 图鉴包含全部 20 件挂件、云游纪念品和岛屿装饰；未获得的藏品保留在图鉴中并以统一灰影展示。用户已确认此范围。
- 云游采用横向路线卡，路线插画成为主要视觉区域，伙伴、路线信息、时长、状态和操作围绕插画排布。用户认可预览方向。
- 回廊地砖、栅栏、机关和怪物统一采用美术总表中的奶油色、暖棕圆描边与柔和贴纸风。用户认可预览方向，并明确要求怪物必须画成可辨认的角色插画，不能继续用圆圈占位。
- 专注开始按钮使用项目主色和纸感实体阴影，与全局面板保持统一。用户认可预览方向。

## 3. 页面与交互设计

### 3.1 伙伴图鉴详情

- Web 宽屏弹窗目标宽度约 740px，最大高度不超过可视区域的 82%。左侧展示约 240–260px 的当前形态主图；右侧展示名称、情绪、羁绊/收服信息、培育进度，以及晴态、虹态、星宿、深流四种形态。
- 四张形态卡都可选择。选择后主图切换到对应形态；未发现形态保持灰影并标注“未发现”。培育操作仍遵循现有规则。
- 窄屏或窄 Web 窗口改为纵向堆叠，主图宽度随可用空间缩放，四种形态卡保持可触达；页面不得横向溢出。

### 3.2 装扮与纪念品图鉴

- 在现有伙伴图鉴中增加“藏品”入口，使用筛选标签查看“全部、伙伴挂件、岛屿装饰、云游纪念品”。
- 收录 `kSouvenirs` 中的全部 20 件资产。藏品图片使用大色块、等比 `contain` 展示，卡片同时显示名称、类别和拥有状态；拥有多件时显示数量。
- 拥有状态继续读取 `state.roam.souvenirs`，不新增存档字段。商店购买与云游领取现有写入路径保持不变。类别由现有挂件元数据、装扮货架和云游奖励池推导。
- 点击藏品打开详情，展示较大图片、名称、类别/稀有度、拥有状态和数量。未拥有项显示统一灰影与“未发现”，不暴露未实现的获得方式。

### 3.3 伙伴云游

- 派遣路线卡和在途卡使用一致的横向结构；路线插画在宽屏卡片中占主要面积，插画容器保持约 1.8:1 的宽高关系并以 `cover` 裁切场景。
- 派遣卡展示路线名称、简介、时长、当前伙伴和出发操作；在途卡展示大插画、伙伴、剩余/到达状态和迎接操作。
- 小屏纵向堆叠插画与信息区。云游时长、奖励池、领取行为不变。

### 3.4 回廊 tile 与怪物

- 重新绘制 11 类既有回廊资源：地面、栅栏、起点、出口、传送门、木门、陷阱、神龛、跨层传送、钥匙、提灯。保持 256px 格子、同一俯视角、相同描边粗细和阴影方向。
- 地面使用可连续拼接的边缘纹理；栅栏的横竖连接延伸至单格边缘，避免相邻格出现断头、缝隙或明显接缝。起终点、门、机关和道具只在统一地面底图上叠加主体。
- 为十个天气回廊各绘制一只小型心结怪物立绘，透明底、256px 母版，轮廓和颜色对应回廊主题。普通怪和精英怪共用主题立绘；等级、精英标识与可战胜状态用小徽记表达。
- Boss 单格内优先复用对应回廊的原创 Boss 立绘，结算页仍使用现有 Boss 图。所有敌方主体都必须是插画，不以圆形或纯色圆点代替。玩家伙伴仍显示现有伙伴立绘。
- 迷宫规则、怪物等级、碰撞、通关和奖励不改变。随机生成结果不依赖美术资源。

### 3.5 界面贴纸图标与美术台账

- 盘点此前由 Emoji 替换成通用 Material 图标的高频产品语义图标，优先接入项目自有 UI 贴纸资源；缺少的图标由 AI 按统一基座补画。关闭、返回、展开、方向键等通用操作控件继续使用标准控件图标。
- 专注开始按钮使用暖橙主色、暖棕描边、底部实体阴影和现有开始贴纸图标，按钮高度至少 48px；禁用状态仍清楚表达“先选择一位伙伴”。
- 在 `docs/08-美术资产描述总表.md` 登记每项新增或重绘资产的用途、尺寸、透明/拼接规则、中文描述和生成 prompt 片段；在 `docs/06-AI美术资产管线.md` 更新数量和部署清单；在 `assets-src/ledger.md` 记录工具、prompt、seed 可用性、后处理与验收结果。
- 新资源遵循源文件 `assets-src/` → 校验/manifest → `app/assets/` 的现有流程。提示词明确资产为本项目原创，不使用参考原型素材。

## 4. 边界与不做事项

- 不改云游时长、掉落、经济、培育、迷宫随机数、等级战斗和存档语义。
- 不重绘已经满足用途的全岛场景、角色立绘或应用图标。
- 不让 UI 贴纸替代文字标签；关键状态始终同时有文本表达。
- 不新增系统 Emoji 字形作为美术资源的临时替代。

## 5. 验收标准

1. Web 宽屏的角色详情能明显放大主体立绘，四形态状态清楚；窄屏可纵向浏览且无裁切、溢出。
2. 藏品图鉴显示全部 20 件，过滤类别正确；购买/云游获得后状态和数量与现有存档一致，未获得项灰影清晰。
3. 云游各路线插画显著大于现有缩略图，派遣与在途信息不拥挤，窄屏可读。
4. 回廊地面、栅栏和功能格在连续布局中边缘相接；各回廊普通/精英怪和 Boss 都显示原创角色插画，等级和状态标识仍可读。
5. 需重绘或新建的图标已登记在美术总表、资产清单和生成台账，并通过资产校验后部署。
6. 专注按钮在纸感面板上具备统一描边、主色、图标、点击面积和禁用状态。
7. Web 与 Android 使用同一套变更后的页面、图标资源和迷宫插画映射。
