# 心晴屿 Moodisle · 逻辑内核详细设计

> v1.0。本文件是 `domain/` 的实现规格：所有公式、状态机、边界行为以本文为准；与 GDD 冲突时以本文为准并回改 GDD。
> 内核为纯 Dart（零 Flutter 依赖），一切随机经注入（§8），一切「今天」用本地日历（§9）。

---

## 1. 设计原则

1. **纯函数内核**：引擎方法形如 `(state, input) → (newState, events[])`，不做任何 IO；UI/存储都是内核的订阅者。
2. **确定性可重放**：给定初始存档 + 输入序列 + 种子，重放结果逐位一致——这是属性测试与「每日回廊」的基础。
3. **单一经验入口**：`grantExp()` 是唯一经验入账点，升级结算只在其中发生。
4. **零惩罚不变式**：任何失败路径不允许出现「负数变化量」的资产操作（编译期用不可负类型封装数量字段）。
5. **本地日历**：`LocalDate` 由 `DateTime.local()` 推导（y/m/d 取本地值），全项目禁止 `toUtc/ISO 截断` 式日期。

## 3. 随机源策略（SeedRegistry）

| 系统 | 种子 | 说明 |
|---|---|---|
| 回廊生成 | `h(localDate) ^ zoneIndex*2654435761` | 每区每日一图，罗盘比拼可复现 |
| 回廊罗盘校验 | 上者 | 结算回放验证步数合法性 |
| 回廊内事件/掉落 | 运行期 RNG（可注入 `Random`，默认系统熵） | 不要求可重放 |
| 共演掉落 / 开箱 / 云游 | 运行期 RNG | 同上 |
| 灵感时刻（完成待办 18%） | 运行期 RNG | |

规则：内核构造函数统一接收 `Random Function rng`；测试注入固定种子。**存档不保存 RNG 状态**（无跨进程一致性需求）。

## 4. 本地日历与跨天（日期引擎）

- `today()`：设备本地时区取 y/m/d。
- `ensureDaily(state)`：每次内核入口（前台恢复/任意写操作前）调用；`date != today` → 滚动：清 `checkedToday`（保留 `checkinDays` 由签到逻辑续算）、重置每日任务槽、重投雾露、`todayMin=0`、周窗口滑动（`weekMin` 改为按周一起算的 `weekStart` 分桶）。
- 7 日窗口数据结构：`hist7d` 为环形数组（7 槽，每槽 `{stress, relief, focusMin}`），跨天时指针前进、新槽清零。

## 5. 收服管线规格（`CaptureEngine.complete(taskId, feedback?)`）

```
前置: task.status != done
1  task.status = done
2  pet = pets[emotion] ?? 新建; pet.count++
3  newStage = count>=10 ? awakened : count>=5 ? rainbow : clear
4  evolvedStage = newStage > pet.stage
5  if newStage == awakened && pet.branch == null:
      branch = turmoil(=pets[anxious].count + pets[chaos].count)
             > persistence(=streak.sunnyDays + resonance.best)
             ? deepcurrent : constellation          // 平局判星宿线
6  res = ResonanceEngine.advance(emotion)          // §6: {linked, len, expBonus, litBonus, gift?}
7  streak: lastSunny==today ? 不变 : (lastSunny==yesterday ? sunnyDays+1 : 1); lastSunny=today
8  fogBonus = climate.tier 含雾 ? 1.2 : 1.0
9  clearing += round((7 + keeperLightBonus) * fogBonus) + res.litBonus   // cap 100
10 energy += 1
11 expGain = 25 + res.expBonus + (feedback!=null ? 2 : 0) + (rng<0.18 ? 20 : 0)
12 keeper: exp += expGain; while exp>=100: exp-=100, level++, 解锁事件入列
13 climate.recompute()                              // §7, 可能产生 ClimateShifted
14 每日任务 bump(task +1, chain max len)；成就扫描
15 yield 事件: TaskCaptured{...}, (EvolutionRevealed?), (KeeperLevelUp?), (ResonanceFired?), 复盘询问
```

### 5.1 算例（验收用例 TC-CAP-001）

前置：`pets[anxious].count=4`（晴态），`pets[emo]` 存在；`resonance={last:shy, len:2}`（霞→雷 承接，见 §6 新环序）；连晴 3；`keeper{lv3, exp55}`（加成：寻宝+3%、点亮+0）；气候 fog=48（薄雾）。
输入：完成「写周报」`{emotion:anxious, diff:2}` + 复盘 😊；灵感未触发。

| 步骤 | 结果 |
|---|---|
| 计数 | anxious 4→5 → 跨入虹态 `EvolutionRevealed` |
| 共鸣 | `NEXT[shy]=anxious` ✓（霞→雷 承接）续链 len 2→3 → `expBonus=20, litBonus=2`，共演掉落虹晶×1 + 链3 里程碑虹晶×1 = 共 +2 → `ResonanceFired` |
| 连晴 | 今日首次 → sunnyDays 3→4 |
| 放晴 | `round(7×1.2)=8 + 2 = 10` |
| 经验 | `25+20+2=47`；keeper 55+47=102 → **lv4, exp=2**；lv4 解锁：每日回廊 +1 → `KeeperLevelUp` |
| 行动力 | energy +1 |

## 6. 天气共鸣引擎

- 状态：`{last: Emotion?, len, best, lastAt: DateTime?}`。
- `advance(e)`：`linked = last!=null && NEXT[last]==e && now-lastAt <= 24h`；`len = linked ? len+1 : 1`；`last=e; lastAt=now`；`best=max`。
- 奖励：`expBonus=(len-1)*10`（len≥1）、`litBonus=(len-1)*1`；`len==3 → gift 虹晶`；`len==5 → gift 暖锋`（各仅跨阈值那一次）。
- 断链 = `linked==false`：len 重置为 1，无任何扣减。
- **共演事件**只在 `linked && len>=2` 时派发 `ResonanceFired`（UI 找 `pets[last_prev]` 与 `pets[e]` 在各自微气候区播放共演）。

## 7. 气候引擎（`ClimateEngine`）

```
recompute():
  stress = Σ{task pending, createdOn ∈ last7d} difficulty × w(emotion)   // w: anxious/neikao 1.3, emo/burnout 1.1, else 1.0
  relief = 2×done(7d) + focusMin(7d)/15
  fog    = clamp((stress-relief)/(stress+relief+4), 0, 1) × 100
  tier'  = fog<30 ? sunny : fog<60 ? mist : densefog
  // 防抖：tier' != tier 时 tierHold++；tierHold>=2 或 |fog'-fog|>25 才切换，否则保持
  // 特殊层（虹光/极光/星雨/暮雪）为叠加显示位，独立判定，不参与 fog 数值
雾露投放（ensureDaily 内）: densefog 4, mist 2, else 0; 暮雪日 +1; cap 5/日
```

算例（TC-CLI-001）：未完成 6 件（焦虑×2 难3 → 7.8；内耗×2 难2 → 5.2；拖延×1 难1 → 1.0）→ stress = 14.0；近 7 天完成 2 件、专注 0min → relief = 4.0；fog = (14−4)/(14+4+4)×100 = **45.5 → 薄雾**（雾露 2/日）。
边界：stress=relief=0 → fog=0（分母 +4 保证）；全清空时气候恒晴。

## 8. 专注引擎状态机（`FocusEngine`）

```
Idle ──start(pet,plan)──▶ Focusing
Focusing ──tick──▶ Focusing                    # 累计 doneMin（含暂停补偿）
Focusing ──appPaused──▶ Glancing(now=ts)       # 精灵张望
Glancing ──resume ≤120s──▶ Focusing            # 无缝继续
Glancing ──>120s 或用户放弃──▶ Voided          # 本次作废；glances+1；零惩罚
Focusing ──doneMin==planMin──▶ Completed       # 结算(§8.1) → Idle
任意 ──cancel──▶ Voided
```

- 计时补偿：`doneMin` 由「累计聚焦时长」推导（`accumulate(now - lastResumeAt)`），不受进程挂起影响；离线（App 被杀）→ 回启时按 `startedAt+plan` 判定：若墙钟已完成且离开发生在完成点之后 → 视为 `Completed`（补结算）；否则 Voided。
- 深潜提醒：`doneMin` 过 25/50 时发通知事件（跨进程由通知桥执行）。

### 8.1 完成结算

```
bond.minutes += planMin(实际 doneMin)
bondLevel' = 首个 thresholds[i] <= minutes 的 i+1     // thresholds=[25,75,150,300,600,1000,1600,2400,3600,5200]
stardust = floor(doneMin/5 × tierMul × (1 + bondLevel×0.05))   // tierMul: 15→1, 25→1, 50→1.5, 自定义→1
events: FocusCompleted{stardust, bondGain, bondLevelUp?}
```

算例（TC-FOC-001）：羁绊累计 50min（Lv1）+ 25min 标准 → minutes=75 → **升 Lv2 相熟**；星屑按**结算前等级**计算 = ⌊25/5 ×1×(1+1×0.05)⌋ = 5。

## 9. 边界与异常行为表

| 场景 | 行为 |
|---|---|
| 跨天瞬间在专注 | 会话归属按「开始日」计周窗；ensureDaily 不打断进行中会话 |
| 系统时间回拨/改时区旅行 | 结算类（云游/专注）用 `max(wallClock, monotonicSinceBoot)` 双钟取大；日期类按设备本地日历，接受跳变（签到按新本地日重算，零惩罚） |
| 24h 共鸣窗口 vs 跨天 | 窗口按真实时间戳，与日期无关；跨天不清共鸣链 |
| 云游到点时 App 关闭 | 回启时统一 `settleRoams()`：按时间戳结算全部到期槽 |
| 行动力/次数双门槛 | 消耗顺序：先校验后扣减，单事务；中断回廊不返还（已在弹层确认） |
| 存档损坏 | JSON/DB 读取失败 → 备份文件降级加载；两者皆坏 → 新档 + 明确告知（不静默清档） |
| 多端并存 | 无云同步（V2 评估）；单设备为准，导入码社交不携带数值 |
