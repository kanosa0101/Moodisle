## 2. 当前实现分层

```
app/lib/main.dart
  MaterialApp / AppShell：五项底部导航、成长入口、首次引导
  presentation/pages：心屿、待办、图鉴、回廊、专注、成长
  application/GameController：状态通知、计时心跳、业务编排、保存调度
  domain/GameCore + engine/entities：游戏状态与领域规则
  data/SqliteGameRepository + Drift：关系表、事务式状态保存、schema migration
  data/SaveCodec + SaveStore：JSON v2 导入/导出与旧存档一次性迁移
  shared/theme：Moodisle 主题 token 和共用组件
  shared/audio：应用级 BGM/音效服务与页面事件接线
```

- 页面使用 Flutter Material 组件和自绘画布；GameController 以 ChangeNotifier 通知 UI。
- GameCore 与领域实体承载任务、收服、气候、专注、生态和回廊逻辑。
- `main.dart` 在生产启动时注入 `SqliteGameRepository`；`GameController` 通过 `GameRepository` 持久化，领域对象和规则不依赖数据库库。
- 第三方运行时依赖包括 Drift、drift_flutter、path_provider 与 just_audio。10 个本地合成 SFX 与 3 首用户提供 BGM 已加入运行时资源；两端实听验收已于 2026-10-01 用户实测通过。

## 3. 存档和生命周期

- SQLite 是自动保存的主存储，Drift schema 当前为 v1；JSON v2 是手动导入/导出格式，两种版本号彼此独立。
- Android/iOS 使用应用文档目录下的 `moodisle.sqlite`；Web 使用随包提供的 Drift WASM 与 worker，并由 Drift 根据浏览器能力在 OPFS、IndexedDB 等存储实现间选择。若浏览器禁用持久化 API，Drift 可能退到内存存储；此时刷新会丢失会话数据。浏览器隐私模式及 Android Chrome 多标签行为需按目标浏览器单独验收。
- Web 资源来自 Drift 官方 `drift-2.35.2` release：`app/web/sqlite3.wasm`（SHA-256 `FBCD2E8214F9231EA961E1B7706A22DD1194CFBFE6F26F13841B5AA7A0BE1A1F`）和 `app/web/drift_worker.js`（SHA-256 `191FC9DB018D2BBECB1723E81118FCF2C5C094DF8644C2FCBA2ED51DF061E90A`）；部署服务需将 `.wasm` 作为 `application/wasm` 提供。
- 首次启动时若数据库还没有玩家档案，读取并校验旧 JSON 主档/备份，写入关系表后继续使用 SQLite。后续启动优先从 SQLite 恢复；旧 JSON 文件保留作迁移/降级来源。
- 一个完整状态快照在单个 SQLite 事务内替换，任务、伙伴、物品、成长、每日进度、云游社交及活动迷宫分别存于关系表。派生伙伴形态/羁绊等级和迷宫地形由现有规则计算，不重复存储。
- GameController 在首次状态变动后约 2 秒合并保存；专注计时使用 1 秒心跳。
- 专注流程接收 Flutter 应用生命周期变化；不同浏览器对标签页隐藏的生命周期语义仍需单独验收。
- 如果 SQLite 初始化/读写失败，控制器尝试旧 JSON 存档并切换到 JSON 降级保存；若没有可恢复存档，会告知用户并启动新档。云同步不是当前能力。
- SQLite 的模块结构、ER 关系、29 张表的字段定义和当前完整性边界见 [数据库设计文档](10-数据库设计.md)。

## 5. 开发与验证

在 app/ 目录执行：

    flutter pub get
    flutter run -d chrome
    flutter analyze
    flutter test
    flutter build web --release --pwa-strategy=none
    flutter build apk --release

iOS 从仓库的 **Actions → iOS Build → Run workflow** 手动构建。`unsigned-app` 默认只执行一次 `flutter build ios --release --no-codesign` 并保留 3 天；`signed-ipa` 复用同一次编译结果完成本地签名。工作流没有 `push`、`pull_request` 或定时触发器，同一分支的新任务会取消旧任务，以减少 macOS runner 使用和产物存储。签名 secret 与真机清单见 docs/09 §2、§5。

微信小程序只在 `feat/wechat-miniprogram` 分支交付（`wechat-miniprogram-spike.yml`，Windows 开发机不做本地构建，工具链约束与平台触点差异见 [12-微信小程序适配](12-微信小程序适配.md)）：构建期自动完成资产瘦身与依赖适配，产物发布到固定 prerelease `weapp-spike-latest`，本地解压至 `app/build/weapp/`（gitignored）供微信开发者工具导入。
